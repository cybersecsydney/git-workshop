\frametitle{What is Git?}
    Git is a \textit{Distributed Version Control System} created in 2002 by Linus Torvalds to manage the Linux Kernel. \\
    \pause
    \begin{itemize}
        \item A version control system stores the files and folders with a log of their changes. This is called a repository (repo for short).\pause \\
        \item A distributed version control system gives each client a complete copy of this database and files. \\
    \end{itemize}
    \pause 
    Unlike systems like Google Docs, Git only stores the state of the repository at specific points called \textbf{commits}. \\
    \pause
    When a commit is created Git takes a snapshot of the repository at that point and refers to it using a sha1 hash. 
\end{frame}

\begin{frame}[fragile]
    \frametitle{Creating a repository}
    We create a repository using
    \begin{codebox}
      git init
    \end{codebox}
    \pause
    This creates a hidden folder called ``\textit{.git}'' which stores the internal git files \\
    \pause
    To ``clone'' an repository from a remote server we can use
    \begin{codebox}
        git clone https://github.com/cybersecsydney/git-workshop.git
    \end{codebox}
    \pause
    This gives us a complete local copy of the repository, including the full history \\
    We can also clone using the ssh protocol instead of https

\end{frame}

\begin{frame}[fragile]
    \frametitle{Git identity}
        Before we can commit anything we need to tell Git who we are. 
        \pause
        \begin{codebox}
        git config user.name "Noah"
git config user.email "noah@quackmail.com.au"
        \end{codebox}
        If we don't want to repeat this for each repository we can add the '\texttt{--global}' flag. \\
        \pause
        We can view the repository or global config using 
        \begin{codebox}
            git config --edit --global
        \end{codebox}
        This can be used to store authentication tokens. 
    
\end{frame}

\begin{frame}[fragile]
    \frametitle{Files}
    Files in a Git repository can be in one of several states. 
    \pause
    \begin{itemize}
        \item Untracked \pause
        \item Unmodified \pause
        \item Modified \pause
        \item Staged \pause
    \end{itemize}
    When we first create a file it is untracked \\
    Before we can commit a file we need to \textit{stage} it for next commit by adding it to the \textit{staging area}
    \begin{codebox}
        git add filename.txt
    \end{codebox}
    \pause
    ``git add'' can be thought of as the ``add this to the next commit'' command. \\
    \pause
    \begin{block}{Warning}
        Don't commit environment files
    \end{block}

\end{frame}

\begin{frame}[fragile]
    \frametitle{Files cont.}
    Before we commit we should inspect the staging area using:
    \begin{codebox}
        git status
    \end{codebox}
    \pause
    Once we are happy with the staging area we commit it
    \begin{codebox}
        git commit
    \end{codebox}
    \pause
    There are numerous useful options such as
    \begin{itemize}
        \item \texttt{-m <msg>}
        \item \texttt{-S}
    \end{itemize}
    Once we've made this commit we can push it to the remote repo using:
    \begin{codebox}
        git push
    \end{codebox}

    \begin{block}{Remark}
        Filenames in ``.gitignore'' are automatically ignored by git. 
    \end{block}

\end{frame}

\begin{frame}[fragile]
    \frametitle{Removing files}
    Similarly to add we can remove files from the staging area.
    \begin{codebox}
        git rm --cached filename.txt
    \end{codebox}
    \pause
    Or if we want to untrack and remove a file
    \begin{codebox}
        git rm filename.txt
    \end{codebox}
    \pause
    \begin{block}{Remark}
        This doesn't remove the file from the history.
    \end{block}

\end{frame}

\begin{frame}[fragile]
    \frametitle{History}
    To view previous commits run
    \begin{codebox}
        git log
    \end{codebox}
    \pause
    Commits are referred to by a sha1 hash, for example 
    \begin{codebox}
        d05e2ac13494daf33d26004d52f577bea19c9e52
    \end{codebox}
    There are various options to modify the output format, including \texttt{--pretty}.
    It is displayed using the Unix command \textit{less}
\end{frame}

\begin{frame}[fragile]
    \frametitle{Diff(erence)}
    \begin{codebox}
        git diff
    \end{codebox}
    This command is used to show the line by line difference between any two commits, or the staging area, or the working directory. \\
    \pause
    To see the difference between the latest commit on two different branches
    \begin{codebox}
        git diff main some-branch
    \end{codebox}
    \pause
    To see the difference between the current working directory and a commit 
    \begin{codebox}
        git diff HEAD
    \end{codebox}
    \pause
    \begin{block}{Remark}
        \textit{HEAD} is a pointer the latest commit on the current branch
    \end{block}
\end{frame}

\begin{frame}[fragile]
    \frametitle{Rewriting history}
    There are multiple ways to undo things in Git, but some of these cannot be undone so you may lose work. \\
    There are four main commands used
    \pause
    \begin{itemize}
        \item \begin{codebox}
                git reset
            \end{codebox}
        \pause
        \item \begin{codebox}
                git revert
            \end{codebox}
        \pause
        \item \begin{codebox}
                git commit --amend
            \end{codebox}
        \pause
        \item \begin{codebox}
                git checkout
            \end{codebox}
    \end{itemize}
    \pause
    \begin{block}{Remark}
        Some classes will mark you down if you include junk files in your repository, this is how you will remove them
    \end{block}

\end{frame}

\begin{frame}[fragile]
    \frametitle{git reset}
    \begin{codebox}
        git reset <commit>
    \end{codebox}
    This is used to change the commit which HEAD points to, allowing it to be used to undo commits amount other things. \pause It has three main modes:
    \begin{itemize}
        \item \texttt{--soft}. This leaves your working directory unchanged and keeps staged changes. \pause
        \item \texttt{--mixed}. This leaves your working directory unchanged but unstages changes. \pause
        \item \texttt{--hard}. This overwrites your working directory and unstages changes, \textbf{meaning you lose any uncommitted changes}. \pause
    \end{itemize}
    \begin{codebox}
        git reset HEAD~5
    \end{codebox}
\end{frame}

\begin{frame}[fragile]
    \frametitle{git revert}
    Git revert makes a new commit that undo the changes made by a individual commit \textit{without deleting} that commit. The \texttt{--no-commit} flag is used to put the changes in the staging area instead of automatically creating a commit. 

\end{frame}

\begin{frame}[fragile]
    \frametitle{commit --amand}
    This command is used to modify the most recent commit, allowing the commit message to be changed and files to be added. However it will completely overwrite the old commit. 
\end{frame}

\begin{frame}[fragile]
    \frametitle{git checkout}
    The git checkout command is used to change branches and restore files in the working tree. 
    \pause
    \begin{itemize}
        \item Switching branches (Typically done with \textit{git switch})\pause
        \item Creating branches (Typically done with \textit{git switch} or \textit{git branch})\pause
        \item Navigating to a specific commit \pause
        \item Restore or revert changes in the working tree \pause
    \end{itemize}
    To restore a specific file to the last committed version: 
    \begin{codebox}
        git checkout --file.txt
    \end{codebox}
    \pause
    \begin{block}{Remark}
        A detached HEAD means you are not on any branch
    \end{block}
\end{frame}

\begin{frame}[fragile]
    \frametitle{Git switch}
    \begin{codebox}
        git switch <branch>
    \end{codebox}
    \pause
    Git switch is used to switch branches, it is very similar to \textit{git checkout} and was created to alleviate the confusion created by \textit{git checkout}. \\
    \pause
    \begin{itemize}
        \item \textit{-c}: Creates a new branch
            \pause
        \item \textit{--discard-changes}, \textit{-f}: Proceed even it the index or the working tree is different from HEAD, i.e. discard changes. 
            \pause
        \item \textit{--guess}, \textit{--no-guess}: If the branch is not found but exists in the remote then it fetches that branch. \textit{no-guess} disables this, \textit{guess} is the default. 
    \end{itemize}
    
\begin{frame}[fragile]
    \frametitle{Merging}
    Say we want to merge branches iss53 and hotfix to apply the hotfix to our iss53 branch. We would first switch to the iss53 branch (using git checkout iss53) and then run:
    \begin{codebox}
        git merge hotfix
    \end{codebox}
    \pause
    If there are merge conflicts we will see an error. To resolve these conflicts we need to manually modify the conflicting files. \\
    \pause
    Once the conflicts are resolved stage the changes and continue the merge using: 
    \begin{codebox}
        git merge hotfix --continue
    \end{codebox}
\end{frame}
